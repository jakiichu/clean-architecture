# Сквозные механизмы

Сквозные механизмы (cross-cutting concerns) — это аспекты системы, которые не принадлежат одному конкретному модулю или слою, но пронизывают всю архитектуру. Они не являются бизнес-логикой, но влияют на то, как бизнес-логика функционирует.

## Ключевые принципы

### Изоляция сквозных аспектов

Каждый сквозной механизм должен быть изолирован в одном месте. Нельзя, чтобы логика логирования, обработки ошибок или управления зависимостями дублировалась в каждом модуле.

```typescript
// ✅ Централизованная обработка ошибок в интерцепторе HTTP-клиента
this.http.getInstance().interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      // Обработка истёкшей сессии в одном месте
    }
    return Promise.reject(error);
  }
);

// ❌ Проверка 401 в каждом репозитории отдельно
```

### Прозрачность для бизнес-логики

Domain не должен знать о конкретных реализациях сквозных механизмов. Use-case не знает, используется ли Zustand или Redux для состояния, SecureStore или MMKV для хранения.

### Конфигурируемость

Сквозные механизмы должны управляться конфигурацией, а не хардкодом в слоях:

```typescript
// src/common/config/demoMode.ts
const IS_DEMO_MODE: boolean = process.env.EXPO_PUBLIC_DEMO_MODE === 'true';

export { IS_DEMO_MODE };
```
