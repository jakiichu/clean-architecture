# Комментарии

## Введение

Не углубляться в рассуждения о том, насколько вредны плохие комментарии. Правило просто: хороший комментарий — это комментарий, которого удалось избежать.

## Комментарии не компенсируют плохого кода

Один из наиболее типичных шаблонов: вы пишете код, понимаете, что он непонятен, и пишете комментарий. Стоп! Напишите лучший код вместо комментария.

```typescript
// ❌ Плохо - комментарий пытается объяснить плохой код
// проверить, что сотрудник получает правильное пособие в соответствии с его классификацией
if ((employee.flags & HOURLY_FLAG) && (employee.age > 65)) {
  // вычислить пенсионное пособие
}

// ✅ Хорошо - код сам рассказывает о себе
if (isHourlyEmployeeEligibleForPension(employee)) {
  calculatePensionBenefit(employee);
}
```

## Хорошие комментарии

### Юридические комментарии

Иногда в корпоративные стандарты кодирования входит обязательное выведение юридической информации. Например:

```typescript
// Copyright (C) 2023 Acme Corporation. All rights reserved.
// This code is subject to the Acme Corporation license agreement.
```

### Информативные комментарии

Иногда комментарий служит для предоставления базовой информации:

```typescript
// Возвращает объект, соответствующий pattern
// вида MM(M?)D(D?)YYYY
// "10-OCT-2000" или "9-OCT-2000" или "10OCT2000"
function parseDate(dateString: string): Date {
  // ...
}
```

### Выражение намерений

Комментарий может объяснять почему, а не что:

```typescript
// Мы забраковали логику, основанную на гарантиях
// производителя, так как попали в ловушку уже пять раз
// с другими поставщиками. Старайтесь не верить
// на слово заявлениям производителя о качестве
class Battery {
  private readonly minimumHours = 10;
}
```

### Предупреждения о последствиях

Комментарий может служить предупреждением о серьёзных последствиях:

```typescript
// Внимание! Метод очень медленный!
// НЕ используйте в цикле!
function expensiveComputationThatShouldBeCalledOnce(): void {
  // ...
}
```

### Комментарии TODO

Подходят для обозначения работы, которую нужно выполнить:

```typescript
// TODO: Если бюджет будет одобрен, то заменить класс
// на более разумный способ расчёта с помощью системы правил
function getExpenses(): number {
  // ...
}
```

## Плохие комментарии

### Бормотание

Комментарий, который ничего не объясняет потому что писавший его вынужден писать комментарий:

```typescript
// ❌ Плохо - непонятно, зачем этот комментарий
const i = 0; // Инициализируем счетчик
for (i = 0; i < clients.length; i++) {
  // ...
}
```

### Избыточные комментарии

Комментарий, который ничего не добавляет к коду:

```typescript
// ❌ Плохо - комментарий повторяет очевидное
const name: string; // Имя пользователя
const age: number; // Возраст пользователя
```

### Недостоверные комментарии

Комментарий, который устаревает и становится неправдивым:

```typescript
// ❌ Плохо - комментарий может быть неправдивым через время
// Получает все активные пользователи
// (На самом деле может возвращать неактивных тоже!)
function getActiveUsers(): User[] {
  return users.filter(user => user.registeredMoreThanYearAgo());
}
```

### Журнальные комментарии

Раньше люди добавляли комментарии, документирующие изменения. Для этого есть системы контроля версий:

```typescript
// ❌ Плохо - используйте git вместо этого
// 21.01.2024 - Исправлена ошибка с пагинацией
// 15.01.2024 - Добавлена кеширование результатов
// 10.01.2024 - Переписан алгоритм
```

### Позиционные маркеры

Иногда программисты разбивают файл позиционными маркерами:

```typescript
// ❌ Плохо - шум, затрудняет чтение
// ///////////////////////////////////////////////////////////////
// USER REPOSITORY METHODS
// ///////////////////////////////////////////////////////////////
```

Используйте их редко и экономно. Если вы используете такой маркер, убедитесь, что в файле его не больше одного-двух.

## Хороший баланс

Идеальное количество комментариев = минимум необходимых комментариев для объяснения намерения.

**Правило:** код должен быть ясен сам по себе. Используйте комментарии только когда невозможно выразить намерение через код.

```typescript
// ✅ Хорошо - чистый код + минимальный комментарий
// Используется для обхода известной проблемы JVM с сортировкой массивов размером > 1000
function sortLargeArray(array: number[]): number[] {
  if (array.length > 1000) {
    return quickSort(array);
  }
  return array.sort((a, b) => a - b);
}
```
