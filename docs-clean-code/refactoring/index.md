# Рефакторинг

## Что такое рефакторинг

Рефакторинг — это **изменение структуры кода без изменения его поведения**. Главное слово — «без изменения поведения»: пользователь системы не должен заметить, что внутри что-то двигалось.

Это означает, что **рефакторинг и доработка функционала — разные виды работы**, и смешивать их в одном коммите — плохая идея.

```
Сначала рефакторим (зеленые тесты → рефакторинг → зеленые тесты)
Потом меняем поведение (новый тест → новый код → зеленые тесты)
```

## Зачем рефакторить

- **Чтобы добавить новую функцию было легко**. Если перед новым требованием кодовая база сопротивляется — её сначала надо разобрать.
- **Чтобы баги стали видны**. В запутанном коде ошибки прячутся, в чистом — бросаются в глаза.
- **Чтобы передать код кому-то ещё**. Через год вы сами будете «кем-то ещё».
- **Чтобы код не «гнил»**. Без рефакторинга случайная сложность накапливается до тех пор, пока проект не становится непригодным.

## Когда рефакторить

### Правило бойскаута

> Оставляйте код **чище**, чем он был до вашего прихода.

Каждый раз, когда вы трогаете файл — улучшайте в нём что-то небольшое: переименуйте переменную, выделите функцию, удалите мёртвый код. Через год файл станет неузнаваемо лучше.

### По правилу трёх

Первый раз — пишете как есть. Второй раз — морщитесь, но повторяете. Третий раз — рефакторите.

### Перед добавлением функции

Сделать сложное изменение легко: сначала упростите код, чтобы изменение стало лёгким — потом сделайте лёгкое изменение.

```
Make the change easy, then make the easy change. — Kent Beck
```

### При обзоре кода

Code review — отличный момент для рефакторинга. Если на ревью трудно понять, что код делает, — это сигнал.

### Когда что-то поломалось

После любого инцидента — рефакторинг того места, где случилась ошибка. Пока контекст свеж в голове.

## Когда НЕ рефакторить

- **На пути в продакшен**. Не делайте рефакторинг в hotfix.
- **В коде, который скоро удалят**. Зачем чистить то, чего завтра не будет.
- **Без тестов**. Сначала тесты, потом рефакторинг.
- **«Заодно с другой задачей»**. Получится перемешанный коммит, который трудно ревьюить и невозможно откатить отдельно.

## Дисциплина рефакторинга

### 1. Тесты — обязательны

Рефакторинг без тестов — это **переписывание**. И вы не можете быть уверены, что не сломали поведение.

Если тестов нет — сначала напишите «характеризационные» тесты, фиксирующие **текущее** поведение (даже если оно странное), потом начинайте рефакторить.

### 2. Малые шаги

Каждый шаг рефакторинга должен:
- Менять одну вещь
- Оставлять тесты зелёными
- Быть откатываемым одним движением

```
Шаг 1: переименовать переменную → тесты зелёные → коммит
Шаг 2: выделить функцию → тесты зелёные → коммит
Шаг 3: перенести метод → тесты зелёные → коммит
```

Не пытайтесь сделать всё за один шаг. Не пытайтесь сделать «комбо», где переименование + выделение + перенос в одном коммите.

### 3. Не смешивать с новым поведением

Если в процессе рефакторинга появилась идея «а заодно добавлю фичу» — **запишите её в TODO и продолжайте рефакторить**. Сделаете отдельным коммитом.

### 4. Используйте IDE

Современные IDE умеют делать многие рефакторинги безопасно:
- Rename Symbol (F2 в VS Code)
- Extract Function/Method
- Move to file
- Change Signature

Они меняют все вхождения, проверяют ссылки, не ломают синтаксис.

### 5. Запускайте тесты часто

После каждого маленького шага. Не через десять. Не «когда закончу». **После каждого**.

## Цикл рефакторинга

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  ┌──────────────────┐   ┌───────────────┐                │
│  │ Проанализировать │ → │  Найти запах  │                │
│  └──────────────────┘   └───────┬───────┘                │
│                                 ↓                        │
│         ┌───────────────────────────────────┐            │
│         │  Выбрать технику рефакторинга     │            │
│         └────────────────────┬──────────────┘            │
│                              ↓                           │
│         ┌─────────────────────────────────┐              │
│         │  Прогнать тесты — должны быть   │              │
│         │  зелёными                       │              │
│         └─────────────────┬───────────────┘              │
│                           ↓                              │
│         ┌────────────────────────────────┐               │
│         │  Сделать маленькое изменение   │               │
│         └─────────────────┬──────────────┘               │
│                           ↓                              │
│         ┌────────────────────────────────┐               │
│         │  Прогнать тесты снова          │               │
│         └─────────────────┬──────────────┘               │
│                           ↓                              │
│           Зелёные? → коммит → следующий запах            │
│           Красные? → откат, попробовать иначе            │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

---

> Рефакторинг — не редкая операция, которую делают «когда есть время». Это **постоянный фоновый процесс**, такой же привычный, как написание новых функций.
