# Каталог техник рефакторинга

Краткий обзор основных приёмов. Подробности по самым важным — в отдельных главах.

## Композиция функций

| Техника | Когда применять |
|---------|-----------------|
| **Extract Function** | Кусок кода требует комментария «что он делает» |
| **Inline Function** | Тело функции говорит само за себя, обёртка не нужна |
| **Extract Variable** | Сложное выражение трудно читать |
| **Inline Variable** | Имя переменной не добавляет смысла |
| **Replace Temp with Query** | Локальная переменная нужна только для одного использования |

## Перемещение функций

| Техника | Когда применять |
|---------|-----------------|
| **Move Function** | Функция в одном модуле, а работает с данными из другого |
| **Move Field** | Поле живёт не в том классе, где должно |
| **Slide Statements** | Связанный код разбросан по функции |

## Организация данных

| Техника | Когда применять |
|---------|-----------------|
| **Encapsulate Variable** | Прямой доступ к переменной мешает рефакторить дальше |
| **Replace Magic Number** | Цифра без объяснения встречается в коде |
| **Encapsulate Collection** | Возвращаете список наружу — клиенты его меняют |
| **Replace Primitive with Object** | За примитивом стоит «понятие» (Money, Email, PhoneNumber) |

## Упрощение условий

| Техника | Когда применять |
|---------|-----------------|
| **Decompose Conditional** | Длинное if-else трудно читать |
| **Consolidate Conditional** | Несколько проверок ведут к одному действию |
| **Replace Nested Conditional with Guard Clauses** | Глубокая вложенность из-за вложенных if |
| **Replace Conditional with Polymorphism** | Switch по типу повторяется в нескольких местах |
| **Introduce Special Case** | Особый случай (например, отсутствующий пользователь) обрабатывается всюду одинаково |

## Упрощение вызовов функций

| Техника | Когда применять |
|---------|-----------------|
| **Rename Function** | Имя не отражает того, что функция делает |
| **Change Function Declaration** | Параметры неудобны или неправильно названы |
| **Introduce Parameter Object** | Группа параметров постоянно ходит вместе |
| **Remove Flag Argument** | Булев параметр включает «другое поведение» |
| **Replace Parameter with Query** | Параметр функция может получить сама |
| **Separate Query from Modifier** | Функция и возвращает значение, и меняет состояние |

## Работа с обобщениями

| Техника | Когда применять |
|---------|-----------------|
| **Pull Up Method** | Один метод повторяется в нескольких подклассах |
| **Push Down Method** | Метод базового класса нужен только одному подклассу |
| **Extract Superclass** | Два класса имеют схожие поля и методы |
| **Extract Interface** | Несколько классов реализуют общий контракт |
| **Replace Inheritance with Delegation** | Подкласс использует мало из базового класса |
| **Replace Subclass with Fields** | Подклассы отличаются только значениями полей |

## Большие изменения

| Техника | Когда применять |
|---------|-----------------|
| **Split Module** | Модуль / класс отвечает за несколько вещей |
| **Combine Modules** | Два модуля делают почти одно и то же |
| **Replace Loop with Pipeline** | Цикл смешан с фильтрацией, маппингом, агрегацией |
| **Replace Type Code with Subclasses** | Поле-строка определяет поведение объекта |

## Микро-каталог самых частых

В реальной работе 80% рефакторинга делается тремя-четырьмя техниками:

1. **Rename** — переименование
2. **Extract Function** — выделение функции
3. **Inline Function** — встраивание функции
4. **Move Function** — перемещение функции

Освойте их безупречно — и большая часть «грязного» кода станет «чистым».

## Карта применения

```
Запах кода                       → Техника
─────────────────────────────────────────────────────────────
Длинная функция                  → Extract Function
Дублирование                     → Extract Function + Move
Длинный список параметров        → Introduce Parameter Object
Большой класс                    → Extract Class
Feature Envy                     → Move Function
Магическое число                 → Replace Magic Number
Длинный switch                   → Replace Conditional with Polymorphism
Загадочное имя                   → Rename
Цепочка вызовов                  → Hide Delegate
Анемичная модель                 → Move Function (логику к данным)
Глубокая вложенность             → Replace Nested with Guards
```
