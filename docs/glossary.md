# Глоссарий

Данный раздел содержит определения ключевых терминов, используемых в документации по архитектуре. Термины сгруппированы по областям для удобства навигации. Глоссарий является живым документом и обновляется по мере развития проекта.

---

## Архитектурные термины

| Термин | Определение |
|--------|-------------|
| **Слой (Layer)** | Архитектурный уровень с чёткой зоной ответственности: `App`, `Domain`, `Data`. Слои взаимодействуют только через явные контракты. |
| **Domain (Ядро)** | Центральный слой системы. Содержит бизнес-правила, сущности, use-case и интерфейсы для внешних зависимостей. Не зависит от фреймворков и инфраструктуры. |
| **Use-case** | Атомарный бизнес-сценарий, реализованный в слое Domain. Принимает входные данные через Port, применяет бизнес-правила, возвращает DTO. |
| **Port (Контракт)** | Интерфейс, объявленный в Domain, который описывает, *что* должно быть сделано, без привязки к *как*. Реализуется в слое Data. |
| **DTO (Data Transfer Object)** | Структура данных для передачи информации между слоями. Содержит только поля, без поведения. Определяется в Domain. |
| **Entity (Сущность)** | Объект предметной области с идентичностью, поведением и инвариантами. Живёт в ядре системы. |
| **Repository** | Абстракция доступа к источникам данных. Объявляется в Domain как интерфейс, реализуется в Data. |
| **Adapter (Адаптер)** | Компонент слоя Data, который преобразует внешние форматы (API, OS) в доменные DTO и наоборот. |
| **Dependency Rule** | Правило направления зависимостей: внешние слои могут зависеть от внутренних, но не наоборот. Зависимости направлены только внутрь Domain. |
| **Presenter (Презентер)** | Компонент слоя App, который агрегирует данные из use-case, управляет формой и подготавливает структуру для отрисовки в UI. |
| **Orchestration (Оркестрация)** | Координация вызовов use-case, управление навигацией и побочными эффектами в слое App. |
| **Invariant (Инвариант)** | Условие, которое должно оставаться истинным на протяжении всего жизненного цикла объекта или операции. Например: «PIN всегда состоит из 6 цифр». Нарушение инварианта — доменная ошибка. |
| **Boundary (Граница слоя)** | Явная точка перехода между слоями, где данные трансформируются из одного формата в другой. Нарушение границы — признак архитектурного нарушения. |
| **Facade (Фасад)** | Упрощённый публичный интерфейс для доступа к подсистеме. В проекте реализуется через `index.ts` файлы модулей, которые реэкспортируют только публичный API. |
| **Factory (Фабрика)** | Функция или класс, создающий экземпляры зависимостей. Используется вместо IoC-контейнеров: `createAuthRepository()`, `createVerifySmsCodeUseCase(deps)`. |
| **Guard (Страж)** | Компонент или хук, который проверяет условие доступа к экрану и перенаправляет пользователя при несоответствии. Реализуется в layout-файлах Expo Router. |
| **Hook-Adapter (Хук-адаптер)** | Паттерн в App-слое: React-хук, который создаёт зависимости (use-case, репозитории) и возвращает данные/методы для компонента. Точка внедрения зависимостей в React-экосистеме. |
| **ADR (Architecture Decision Record)** | Документ, фиксирующий архитектурное решение: контекст, рассмотренные варианты, обоснование выбора и последствия. Позволяет команде понять, почему система устроена именно так. |

## Термины управления состоянием

| Термин | Определение |
|--------|-------------|
| **UI State** | Состояние, отвечающее за визуальное отображение: флаги загрузки, значения полей, видимость элементов. Управляется в App. |
| **Server State** | Данные, источником которых является внешний API. Требуют кэширования, инвалидации и синхронизации. Управляются клиентами запросов (TanStack Query). |
| **Business State** | Инварианты и вычисляемые результаты предметной области. Не хранятся, а вычисляются в Domain при каждом вызове use-case. |
| **Persistent State** | Данные, сохраняемые между перезапусками приложения: токены, настройки, криптографические ключи. Хранятся через адаптеры в Data. |
| **Stale Time** | Время, в течение которого кэшированные данные считаются актуальными и не требуют повторного запроса. |
| **GC Time (gcTime)** | Время, в течение которого неактивные кэшированные данные хранятся в памяти после того, как подписчики отключились. По истечении — данные удаляются из кэша. |
| **Invalidation (Инвалидация)** | Процесс пометки кэшированных данных как устаревших, что инициирует их повторную загрузку при следующем обращении. |
| **Refetch (Рефетч)** | Повторный запрос данных к источнику, инициированный программно или по таймеру. |
| **Optimistic Update** | Обновление UI до получения ответа сервера, с откатом при ошибке. Допустимо только для некритичных действий. |
| **Pessimistic Update** | Обновление UI только после успешного ответа сервера. Обязательно для финансовых операций, авторизации и критичных действий. |
| **Query Key** | Уникальный идентификатор запроса в TanStack Query. Используется для адресации кэша при инвалидации. Объявляется в константе `QUERY_KEYS`. |
| **Mutation (Мутация)** | Операция изменения данных (POST/PUT/DELETE), управляемая через `useMutation`. Не кэшируется, выполняется по требованию. |
| **refetchInterval** | Параметр `useQuery`, задающий интервал автоматического рефетча в миллисекундах. Используется для polling и таймеров ротации. |
| **networkMode** | Настройка TanStack Query, определяющая поведение запросов при отсутствии сети: `'online'`, `'always'`, `'offlineFirst'`. |

## Мобильная и нативная специфика

| Термин | Определение |
|--------|-------------|
| **Native Module** | Код, написанный на платформенном языке (Swift/Kotlin) и доступный в React Native через мост (Bridge). |
| **SecureStore / Keychain / Keystore** | Аппаратно-защищённые хранилища ОС для криптографических ключей, токенов и чувствительных данных. На iOS — Keychain, на Android — Keystore. |
| **Biometric Authentication** | Аутентификация с использованием биометрических данных устройства: Face ID, Touch ID, отпечаток пальца. |
| **Device Fingerprint** | Уникальный идентификатор устройства, формируемый на основе аппаратных и программных характеристик. Используется для привязки сессии к конкретному устройству. |
| **Expo Router** | Файловая система маршрутизации для React Native на основе Expo. Обеспечивает навигацию через декларативные пути, соответствующие структуре директории `app/`. |
| **Metro Bundler** | Сборщик модулей для React Native. Трансформирует исходный код, разрешает зависимости и формирует бандл для запуска на устройстве. |
| **Development Build** | Кастомная сборка приложения для разработки, включающая нативные модули и отладочные инструменты. Отличается от Expo Go поддержкой любых библиотек. |
| **EAS Build** | Облачный сервис сборки Expo Application Services. Позволяет компилировать приложения для iOS/Android без локальной настройки Xcode/Android Studio. |
| **Deep Link** | Ссылка, открывающая конкретный экран приложения из внешнего источника (браузер, email, пуш-уведомление). Конфигурируется через `scheme` в `app.config.ts`. |
| **Safe Area** | Зона экрана, не перекрытая системными элементами (нотч, статус-бар, нижняя панель навигации). Учитывается через `SafeAreaProvider` и `useSafeAreaInsets`. |
| **Gesture Handler** | Библиотека `react-native-gesture-handler`, заменяющая встроенную систему жестов. Необходима для корректной работы навигации и свайпов. |
| **Swipe Back** | Жест смахивания экрана вправо для возврата назад (iOS-паттерн). Реализуется через кастомный `SwipeBackWrapper` или настройки стека навигатора. |
| **Background Task** | Задача, выполняемая в фоновом режиме (когда приложение свёрнуто). На мобильных платформах ограничена системой; `refetchIntervalInBackground: false` отключает polling в фоне. |
| **App State** | Состояние жизненного цикла приложения: `active`, `background`, `inactive`. Используется для управления polling и освобождения ресурсов. |
| **WHEN_UNLOCKED_THIS_DEVICE_ONLY** | Политика доступа к SecureStore: данные доступны только когда устройство разблокировано и только на текущем устройстве (не синхронизируются в облако). |

## Инструменты и библиотеки

| Термин | Определение |
|--------|-------------|
| **TanStack Query** | Библиотека для управления серверным состоянием: кэширование, фоновое обновление, пагинация, обработка ошибок. Используется в слое App. |
| **Zustand** | Минималистичная библиотека управления клиентским состоянием. Применяется для глобальных флагов интерфейса и сессионных настроек. |
| **TypeScript Strict Mode** | Набор строгих правил типизации: запрет `any`, обязательная проверка `null/undefined`, строгая проверка `this`. Обеспечивает безопасность рефакторинга. |
| **Expo Config Plugins** | Механизм настройки нативных проектов (iOS/Android) через декларативный конфиг `app.config.ts` без ручного редактирования Xcode/Gradle. |
| **axios-mock-adapter** | Библиотека для мокирования HTTP-запросов axios в тестах. Позволяет проверять маппинг ответов без реального сервера. |
| **React Testing Library** | Утилита для тестирования React-компонентов, фокусирующаяся на поведении с точки зрения пользователя. Предоставляет `renderHook` для тестирования хуков. |
| **Detox** | Фреймворк для E2E-тестирования мобильных приложений на реальных устройствах или симуляторах. |
| **MMKV** | Высокопроизводительное key-value хранилище для React Native (альтернатива AsyncStorage). Используется для незащищённых настроек и конфигурации. |

## Принципы и паттерны

| Термин | Определение |
|--------|-------------|
| **Inversion of Control (IoC)** | Принцип, при котором управление потоком программы передаётся внешнему компоненту (например, внедрение зависимостей через конструктор). |
| **Dependency Injection (DI)** | Паттерн передачи зависимостей извне, а не их создания внутри класса. Упрощает тестирование и замену реализаций. |
| **Pure Function (Чистая функция)** | Функция, которая при одинаковых входных данных всегда возвращает одинаковый результат и не имеет побочных эффектов. Основа бизнес-логики в Domain. |
| **Side Effect (Побочный эффект)** | Любое взаимодействие с внешним миром: сеть, диск, UI, навигация. Изолируется на краях системы (App или Data). |
| **Fire-and-Forget** | Сценарий выполнения операции без ожидания результата или обработки ошибки. Допустим только для аналитики и некритичных логов. |
| **Composition over Inheritance** | Принцип предпочтения композиции объектов наследованию. В проекте реализуется через фабричные функции с передачей зависимостей. |
| **Single Responsibility** | Принцип: каждый модуль, класс или функция должны иметь одну причину для изменения. Основа разделения use-case и репозиториев. |
| **Graceful Degradation** | Управляемая деградация функциональности при сбоях: приложение продолжает работу с ограниченными возможностями, а не падает. Реализуется через кэш, fallback-экраны и блокировку мутаций. |
| **Demo Mode (Режим демонстрации)** | Конфигурация, при которой сетевые зависимости заменяются mock-реализациями. Позволяет разрабатывать и демонстрировать приложение без реального бэкенда. Управляется флагом `IS_DEMO_MODE`. |
| **Polling** | Паттерн периодического запроса данных через фиксированный интервал. Реализуется через `refetchInterval` в TanStack Query. |
| **Countdown Timer** | UI-паттерн отображения обратного отсчёта до следующего события (обновление кода, истечение сессии). Управляется через `setInterval` в `useEffect`, не через Domain. |
| **Error Boundary** | React-компонент, перехватывающий ошибки рендеринга в дочернем дереве и отображающий fallback-UI вместо падения приложения. |

## Паттерны обработки ошибок

| Термин | Определение |
|--------|-------------|
| **Infrastructure Error** | Ошибка на уровне I/O: сетевой сбой, таймаут, недоступность хранилища. Перехватывается и трансформируется в слое Data. |
| **Domain Error** | Ошибка нарушения бизнес-инварианта: истёкший код, превышение лимита попыток, невалидный формат. Выбрасывается в Domain, содержит `violationRule`. |
| **Presentation Error** | Ошибка отображения или валидации формы. Управляется в App-слое, не доходит до Domain. |
| **isRetryable** | Флаг в интерфейсе ошибки, указывающий, имеет ли смысл повторить операцию. Таймауты и 5xx — retryable, 4xx и доменные ошибки — нет. |
| **Fallback UI** | Запасной интерфейс, отображаемый при ошибке или отсутствии данных. Предотвращает показ пустого экрана пользователю. |
