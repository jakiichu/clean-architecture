# Примеры реализации

В данном разделе собраны пошаговые руководства по реализации типовых сценариев в мобильных приложениях с использованием принципов чистой архитектуры. Каждый пример демонстрирует практическое применение паттернов от описания контрактов в `Domain` до интеграции с UI-слоем в `App`.

Все примеры обезличены и не привязаны к конкретному проекту. Они описывают универсальные мобильные паттерны, которые встречаются в корпоративных, B2C и инфраструктурных приложениях.

## Технологический стек примеров

- **TypeScript** — строгая типизация во всех слоях
- **React Native + Expo** — мобильная платформа
- **TanStack Query** — управление серверным состоянием
- **Zustand** — клиентское UI-состояние
- **Expo Router** — файловая маршрутизация

> TanStack Query используется только в слое `App` для оркестрации запросов через порты `Domain`. Бизнес-логика остаётся независимой от UI и API.

## Каталог примеров

### Получение данных (GET)

**[Пример: GET-запрос →](./feature-get.md)**

Базовый паттерн для загрузки данных с сервера. Покрывает:
- Описание контрактов: DTO, Port, Repository Interface, Use-case Interface
- Реализацию use-case с доменной валидацией входных параметров
- Маппинг ответа API в Domain DTO в слое Data
- Интеграцию с `useQuery`, настройку staleTime и кэширования
- Презентер для агрегации данных, управления фильтрами и состоянием

*Когда использовать:* загрузка списков (уведомления, заявки, история), профиль пользователя, каталоги.

---

### Отправка данных (Mutation)

**[Пример: Мутация (POST) →](./feature-post.md)**

Паттерн для операций изменения состояния системы. Покрывает:
- Специфику мутаций в чистой архитектуре (атомарность, изоляция побочных эффектов)
- Реализацию `useMutation` с обработчиками `onSuccess` и `onError`
- Навигацию и инвалидацию кэша после успешной операции
- Блокировку UI во время выполнения (`isPending`)
- Разницу между Query и Mutation

*Когда использовать:* формы отправки, авторизация, регистрация событий, сохранение настроек.

---

### Нативные модули и аппаратное обеспечение

**[Пример: Интеграция нативных модулей →](./native-integration.md)**

Паттерн адаптеров для изоляции нативных зависимостей. Покрывает:
- Принципы интеграции OS-уровня (SecureStore, биометрия, камера)
- Объявление интерфейса в Domain (независимо от платформы)
- Реализацию адаптера в Data (конкретная нативная библиотека)
- Обработку разрешений и нативных ошибок

*Когда использовать:* SecureStore для токенов, Face ID/Touch ID, камера, геолокация.

---

### Polling и таймер обратного отсчёта

**[Пример: Polling и таймер →](./polling.md)**

Паттерн для данных с ограниченным сроком жизни (TTL). Покрывает:
- Два `useQuery` с разным `staleTime` (зависимые запросы)
- `refetchInterval` для автоматической ротации
- `refetchIntervalInBackground: false` для экономии батареи
- Таймер обратного отсчёта как UI State
- Инвалидацию кэша при истечении таймера

*Когда использовать:* OTP-коды, биржевые котировки, статусы живой очереди, временные сессионные данные.

---

### Многошаговая форма (Onboarding)

**[Пример: Многошаговая форма →](./form-validation.md)**

Паттерн для потоков с несколькими последовательными шагами. Покрывает:
- Передачу данных между шагами через Zustand (не URL-параметры)
- Отдельный хук мутации для каждого шага
- Разделение синтаксической валидации (App/Presenter) и бизнес-правил (Domain)
- Автоматическую отправку при заполнении PIN/SMS (6 цифр)

*Когда использовать:* онбординг, регистрация, смена пароля, мастер настройки.

---

### Оффлайн-режим и деградация

**[Пример: Оффлайн-режим →](./offline-mode.md)**

Паттерн управляемой деградации при потере сети. Покрывает:
- Отслеживание состояния сети через `NetInfo`
- Показ кэшированных данных с пометкой «оффлайн»
- Блокировку мутаций при отсутствии интернета
- Persistентный кэш через `AsyncStorage` (с учётом безопасности)
- Отличие managed degradation от offline-first

*Когда использовать:* любое мобильное приложение с сетевыми запросами.

## Дорожная карта примеров

Планируется добавление следующих примеров:

- **Пагинация и бесконечная прокрутка** — `useInfiniteQuery`, виртуализация списков
- **Загрузка файлов** — изображения, документы, прогресс-бар
- **Push-уведомления** — регистрация токена, обработка в foreground/background
- **Биометрический быстрый вход** — повторная аутентификация через Face ID/Touch ID

---

## Как читать примеры

Каждый пример структурирован по шагам: **Domain → Data → App**. Это порядок реализации, обеспечивающий:
1. Фиксацию контрактов до написания инфраструктуры
2. Независимость бизнес-логики от конкретного фреймворка
3. Возможность параллельной работы над разными слоями

Если конкретная деталь реализации кажется неочевидной, обратитесь к соответствующему разделу документации по ссылкам «Дальнейшее чтение» в конце каждого примера.
